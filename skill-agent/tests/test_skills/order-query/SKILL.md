# 订单查询能力

## 数据来源
订单数据存储在 `data/orders.txt` 文件中，每行一条记录，字段以 `|` 分隔：
- 字段1：订单号（如 ORD-001）
- 字段2：订单状态（待支付、待发货、已发货、已完成、已取消）
- 字段3：商品ID（如 PROD-001）——仅 ID，不是商品名称
- 字段4：用户ID（如 U001）

## 输入 / 输出
- 输入：用户ID 或 订单号（不要用用户名）
- 输出：订单号、订单状态、商品ID、用户ID
- 没有：用户名、电话、邮箱、商品名称、标价、类目、库存

## 数据查询方式
- 读取全部订单：`cat data/orders.txt`
- 按订单号查询：`grep "ORD-001" data/orders.txt`
- 按用户ID查询：`grep "U001" data/orders.txt`
- 按商品ID查询：`grep "PROD-001" data/orders.txt`
- 按订单状态查询：`grep "已发货" data/orders.txt`
- 统计某用户的订单数量：`grep "U001" data/orders.txt | wc -l`

## 支持的查询场景
1. 查询某个用户（已知用户ID）的全部订单
2. 查询某个订单号的详细信息
3. 按订单状态筛选订单
4. 按商品ID反查订单
5. 统计用户的订单数量

## 跨域规划（强制）
- 没有用户ID时不要猜测用户名对应谁；用户名解析不属于本技能。
- **还没有商品ID时**：本轮只执行本技能查订单。不要把商品名称/标价/库存写进当前计划，也不要委派 product_query。先把订单查完，让结果里出现商品ID。
- **上下文里已经有商品ID，且用户仍要名称、标价或库存**：再委派 **product_query**，query 只带这些商品ID 和缺失字段。不要让对方按用户名或用户ID查商品。
- 返回给上游时如实给出商品ID；不要把 ID 说成商品名称。
