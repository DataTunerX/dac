# 智能体列表 · 设计说明（Task-First）

## 1. 关系模型

- **业务智能体**：绑定语义组，面向「一个业务场景 / 一件事」。
- **数据智能体**：绑定数据描述符，面向单点数据检索。
- **组成关系**：语义组的成员是若干数据描述符（通过 dd_group_relations 关联）。因此 **业务智能体所依赖的「数据」由该组内的数据智能体提供** —— 即「业务智能体由数据智能体组成」在场景维度成立。

## 2. 以「做什么事」为入口

- **问题**：按类型平铺（业务 / 数据）只是把筛选拆成区块，业务上仍是在「选类型」而不是「选要做的事」。
- **做法**：**以场景（语义组）为第一入口** —— 语义组 = 一件事/一个业务范围。
  - **一级**：展示「做什么事」= 语义组列表（场景卡片）。
  - **点进某场景**：展示该场景下**涉及到的智能体**：
    - **业务智能体**：绑定当前语义组的智能体（做这件事的入口）。
    - **数据智能体**：绑定到该组内成员描述符的智能体（组成这件事的数据能力）。

## 3. Design Direction

- **Aesthetic**: Industrial / Utilitarian，信息架构服务于「先选事、再看智能体」。
- **Differentiation anchor**：首屏是「场景卡片」而非「智能体卡片」；点进场景后看到「业务 + 组成数据」的两块结构，关系一目了然。

## 4. 路由与页面

| 路径 | 内容 |
|------|------|
| `/agents` | 场景选择（语义组列表），入口「做什么事」。 |
| `/agents/scenario/[groupId]` | 该场景下的智能体：业务智能体 + 数据智能体（组成）。 |
| `/agents/all` | 全部智能体（按类型分区），供「浏览全部」需求。 |
