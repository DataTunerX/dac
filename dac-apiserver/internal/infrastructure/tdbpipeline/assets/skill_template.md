# {{.Title}}

Answer {{.Subject}} questions with TDB as an **evidence system**, not a trivia lookup.
Find reachable knowledge (wiki / ontology / search), walk provenance back to source
text, and use that evidence as a handle to discover more. Organize the final answer
around the question, and treat qualifiers as part of the claim.

## Deployment

- gateway: `{{.GatewayURL}}`, all v2 routes under the `/v2` prefix
- domain: **`{{.Domain}}`** (this is the only correct value — see the guard below)
- collection most recently ingested here: `{{.Collection}}`
- MCP: if using `tdb-memory-server`, point it at this gateway
  (`TDB_GATEWAY_BASE_URL={{.GatewayURL}}`); otherwise call the HTTP endpoints
- answer language: reply in the user's language; default to the language of the
  retrieved evidence
- the corpus grows as sources are ingested; do not hardcode counts or promise
  coverage. Check current scope live via `resolved_stream_ids` from a
  `search/query`, or `GET /v2/search/domain-stream/list`

### How this corpus is loaded

New material reaches this gateway through DAC Data Management → **TDB 入库**
(`/tdb-pipeline`), which submits runs to the TDB pipeline controller with
`domain: "{{.Domain}}"` against target `{{.TargetID}}`. That target writes to this
same gateway, so anything ingested there becomes answerable here. Other gateways
are separate databases and are **not** visible to this skill.

### Domain guard (critical)

Pass `domain: "{{.Domain}}"` and let the gateway resolve streams via its
domain-to-stream binding. A wrong domain does **not** error: `search/query` returns
`resolved_stream_ids: []` and then searches the **entire unscoped corpus**, still
returning hits — silently cross-corpus and wrong.

> Rule: `resolved_stream_ids` is about **scope**, not matches — do not confuse it
> with hit count. After the first `search/query`:
> - empty `resolved_stream_ids` **with** non-empty `hits` -> wrong/unbound domain: the
>   search ran unscoped over the whole corpus. STOP and report a binding misconfiguration.
> - non-empty `resolved_stream_ids` but zero `hits` -> scope is correct, the query just
>   found nothing; rephrase or expand — do **not** treat this as a misconfiguration.
> Sanity-check bindings with `GET /v2/search/domain-stream/list`.

## How to call TDB

Call the HTTP endpoints below directly (if TDB MCP tools are present they wrap these
same endpoints — but do not assume they exist; default to HTTP). For fuller endpoint
details, read `references/gateway_api_doc.md`. **These are evidence-gathering tools,
not an answer engine** — the gateway does not decompose the question or judge
sufficiency for you. You must: (1) understand what the question asks, (2) pick anchors
(concept / page / relation / passage), (3) call these endpoints for local evidence,
(4) decide to expand or stop. Note the HTTP verbs: reads are **GET with query-string
params**; only search and evidence-pack are POST.

Discovery / search:

- `POST /v2/search/query` `{ "query", "domain": "{{.Domain}}", "mode": "hybrid", "limit": 30 }`
  -> `hits` + `resolved_stream_ids` (raw source text). Default `mode:"hybrid"`, but switch
  to **`mode:"lexical"` to find or verify exact terms and enumerated lists** (proper nouns,
  dates, enumerations) — vector similarity can bury an exact match under paraphrase, so
  confirm any verbatim claim with a lexical pass.
- `POST /v2/qa/evidence-pack` `{ "question", "domain": "{{.Domain}}", "wiki_limit": 5, "evidence_limit": 3 }`
  -> `wiki_hits` / `concept_hits` / `fact_hits` in one call — a quick multi-layer discovery
  aid. It shows what TDB recalls from the question text; it does not do multi-hop QA, so
  use it to seed anchors, then drive to statements yourself.

Wiki / ontology / statements: see `references/gateway_api_doc.md` for the full route
list, request shapes and response fields.

## Working method

1. **Read the question.** Decide what would count as an answer, and what evidence
   would support it. A question about a cause needs a mechanism, not a label.
2. **Seed anchors.** Run `evidence-pack` or a `search/query` to find the concepts,
   wiki pages and passages the question touches.
3. **Go to statements.** For each promising anchor, pull statements and their
   provenance. A statement without provenance is a lead, not a fact.
4. **Walk back to source text.** Provenance points at a stream and offset; read the
   surrounding passage. The passage usually contains the qualifier that the triple
   dropped.
5. **Expand or stop.** New entities in the passage are new anchors. Stop when the
   question is answered or when the corpus clearly does not cover it.
6. **Answer the question asked.** Organize around the question, not around the shape
   of the data. Carry qualifiers (time, place, certainty, who claimed it) into the
   claim itself.

## Reporting rules

- Ground every substantive claim in retrieved evidence; cite the stream/passage.
- Say plainly when the corpus does not cover something. Absence of hits inside a
  correctly scoped domain is a finding, not a failure to report around.
- Distinguish what a source claims from what is established. Attribute contested
  claims to their source.
- Do not fill gaps from background knowledge without labelling it as outside the corpus.
