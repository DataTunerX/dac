**Kubernetes**（通常简称为 **K8s**，因为 K 和 s 之间有 8 个字母）是一个开源的**容器编排平台**。

简单理解：当你用 Docker 等容器技术运行了很多个应用，Kubernetes 就是负责**自动管理**这些容器的"大管家"。

---

## 核心作用：解决什么问题？

假设你用 Docker 运行了 10 个微服务，手动管理会遇到很多问题：

| 问题 | Kubernetes 的解决方案 |
|------|----------------------|
| 某个容器挂了，需要有人重启它 | **自动修复**：自动检测并重启失败的容器 |
| 流量突然暴增，需要增加容器数量 | **自动扩缩容**：根据 CPU/内存自动增加或减少容器 |
| 新版本发布，需要平滑升级 | **滚动更新**：逐步替换旧版本，不中断服务 |
| 多个容器如何互相发现和通信 | **服务发现与负载均衡**：自动分配 IP 和 DNS，分发流量 |
| 配置信息分散在各处 | **配置管理**：通过 ConfigMap、Secret 统一管理配置 |
| 数据需要持久化存储 | **存储编排**：自动挂载云存储、NFS 等存储系统 |

## 关键概念

| 术语 | 解释 |
|------|------|
| **Pod** | K8s 最小部署单元，一个 Pod 包含 1 个或多个容器 |
| **Node** | 一台物理机或虚拟机，上面运行多个 Pod |
| **Service** | 为一组 Pod 提供稳定的网络入口和负载均衡 |
| **Deployment** | 管理 Pod 的副本数量、滚动更新、回滚等 |
| **Ingress** | 将外部 HTTP/HTTPS 流量路由到内部 Service |
| **Namespace** | 逻辑隔离的环境，用于区分不同项目/环境 |

## 典型使用场景

1. **微服务架构**：管理几十上百个微服务实例
2. **DevOps 自动化**：与 Jenkins、GitLab CI 集成实现自动部署
3. **混合云部署**：同时在 AWS、Azure、本地数据中心运行
4. **批处理任务**：运行定时任务或一次性计算任务（Job/CronJob）

---

## 优点 vs 缺点

| 优点 | 缺点 |
|------|------|
| ✅ 自动化运维，减少人工干预 | ❌ 学习曲线陡峭 |
| ✅ 弹性伸缩，应对流量波动 | ❌ 小项目过于重 |
| ✅ 自愈能力，提高可用性 | ❌ 调试排障复杂 |
| ✅ 声明式配置（YAML），便于 IaC | ❌ 网络/存储配置有坑 |
| ✅ 社区活跃，生态丰富 | ❌ 版本升级可能有兼容问题 |

---

## 一句话总结

> **Kubernetes 是管理容器化应用的操作系统**，让你像指挥千军万马一样，轻松管理成百上千个容器实例。
